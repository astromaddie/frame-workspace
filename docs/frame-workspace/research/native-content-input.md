The helper associates each connection with its captured source and session ID; the input messages do not name an arbitrary target window. Stream credentials are source-bound. See `ui/mac-view.html:129`, `mac/frame-mac-view/Sources/main.swift:907–910,1426–1454`.

**VERIFIED — coordinate conversion:** `Session.point()` maps normalized coordinates through `capture.frameRect`, clamping each axis to `[0,1]`. For `spatial:WID`, that rectangle is a fresh `WindowInfo.find(WID).bounds`; for all auxiliary sources it is the current global-point `surface.rect`. Thus strips map through their actual menu/status crop, and menu slots through the cropped surface, whether captured as an independent window or fallback display crop. Encoded pixels are not multiplied into input coordinates. See `Sources/main.swift:738–742`, `SpatialShared.swift:83,325,379–385`, `SpatialSharedPolicy.swift:56–58`.

**VERIFIED — focus/raise:** Spatial mouse-down, key-down and text call `ensureFrontmost`; pointer moves and wheel do not. Spatial focus invokes AXRaise, AXMain, AXFrontmost and app activation, updates the fence, and restores per-window normalized cursor memory (first visit uses supplied gaze coordinates). Repeat focus on the same remembered source avoids a cursor teleport. `Input.focus()` ignores AX return values, and `SpatialFocus.focus()` returns success without confirming the actual keyboard-focused window. See `Sources/main.swift:847–880,1473–1479`, `Input.swift:51–74`, `SpatialShared.swift:23–49`, `SpatialStreams.swift:50–63`.

**VERIFIED — held state:** Spatial companion setup enables shared-pointer mode through `/pointer?shared=1` (`ui/frame_macview.py:1016–1019`). A held button is global across panel sessions: moves become dragged events, duplicate downs are suppressed, an up from another session releases it, and disconnect releases buttons originally owned by that session. Keys retain per-session ownership. Double-click counts are computed on the Mac from timing and a five-point proximity check. See `Input.swift:77–129,141–159`, `SpatialStreams.swift:176–213`.

**VERIFIED — what auxiliary input implements:** `menubar`, `status`, and `menu:0…3` reach the same mouse/wheel/key/text switch. Their mouse-down does not AXRaise an app/window because these sources have no PID and are not `.spatial`. Their key/text input goes to the Mac's existing keyboard focus. There is no visible-surface or surface-generation check before injection, so an old idle menu slot can still map against its current/empty rect. See `Sources/main.swift:847–888`, `SpatialShared.swift:311–328`.

**INFERRED — working boundary:** the source implements browser-style window/strip/menu injection, but unrestricted hover onto an unfocused overlapping window is unsafe: it neither raises that window nor relocates its fence. Sending a down to a normal Spatial window takes the intended raise path; success on real applications, modal children and auxiliary surfaces still requires runtime evidence. The repository records overlapping-fixture clicks/keys and menu/status clicks on this Mac/OS, not production native input acceptance (`docs/frame-workspace/SPATIAL.md:567–584`).

## 2. Native building blocks and competing interactions

**VERIFIED — rays and UV:** `surfacePick()` transforms controller/eye rays into the panel's bend geometry, applies picture inset/crop, rejects backfaces, and returns original top-left picture UV. `bendHit()` handles flat, symmetric/asymmetric horizontal and vertical bends. Existing tests round-trip these geometries. However `surfacePick()` also returns clamped edge UV for a bezel/frame-wall hit; a content-input hit must explicitly exclude that fallback and decorative/padded regions. See `native/host.hpp:218–269`, `bend.hpp:151–189`, `tests_host.hpp:38–83`, `tests_spatial.hpp:108–150`.

**VERIFIED — current inputs:** each host frame samples both hand-tip poses and digital `grab`, `squeeze`, `switcher`. Bindings map both triggers → grab, both grips → squeeze, left Y → switcher. Only Frame bindings exist; no scroll analog or native keyboard action is declared. A trigger/grip starts placement only over a handle; its initiating hand retains that placement gesture until release. Picture-content trigger presses have no forwarding implementation. Overlay input method is `None`; overlay event polling handles Quit rather than mouse/key events. See `native/session.hpp:182–231`, `input/actions.json:1–15`, `input/bindings_frame_controller.json:6–15`, `overlay.hpp:671–677,952–1009,1300–1313`.

**VERIFIED — trigger consumers:** shelf/switcher presses latch the initiating hand, click on release over the same tile, and use a 500 ms Dock hold for its app menu. Auxiliary hits block shelf/window routing; shelf tiles block content behind them; an open switcher consumes grip for navigation. I1 is a distinct auxiliary status overlay positioned on the shelf, not a Dock tile. See `native/spatial.hpp:317–334,369–412`, `main.cpp:1463–1521,1536–1557`.

**VERIFIED — gaze:** native focus uses a 250 ms uninterrupted dwell, then writes the companion request and sends stream `focus`; it locally activates the focus glow without a Mac acknowledgement. Eyes are preferred; controller rays are the fallback. Menus/status/shelf suppress focus on underlying windows. Host dwell uses bend-aware geometry, so `Overlay::gaze()` refusing asymmetric/vertical bends affects its separate gaze/foveation-UV path, not this host dwell path. See `native/chrome.hpp:65–80`, `spatial.hpp:123–175`, `main.cpp:1577–1618`, `overlay.hpp:1071–1088`.

**VERIFIED — WebSocket suitability/limit:** each `VideoPipe` already sends text. Focus is a single replaceable pending value; timing reports use an eight-entry drop-when-full queue. These are not suitable semantics for button/key edges. Ordinary streams use 100 ms idle polling and do not service outbound traffic while continuously assembling a video message; only gaze endpoints currently enable 8 ms servicing during reads. Sends can also block the network worker under backpressure. See `native/video.hpp:414–433,442–513`, `websocket.hpp:32–90`.

**VERIFIED / INFERRED — physical keyboard:** the inspected native action/event path contains no keyboard forwarding. The helper activates the chosen Mac app/window, so the physical Mac keyboard follows normal macOS focus (INFERRED runtime consequence, not tested here). The leased Spatial Cmd-Tab tap is the specific exception: it consumes Tab cycling and observes Command release; other keys pass through (`Sources/Apps.swift:287–361`). No headset keyboard, text-entry UI or IME implementation is present in these paths.

## 3. Proposed behavior and wire additions

**INFERRED — single owner:** add a pure `ContentInput` state machine in native, called once per host frame. A press edge latches hand and consumer until release: existing captured placement/UI gesture first; otherwise eligible foreground auxiliary content, shelf/switcher tile, handle, then window picture according to existing render/hit priority. No gesture transfers into content just because a held trigger enters it. Default right hand wins simultaneous new content acquisition; one Mac cursor means the second hand cannot inject concurrently. Expose handle-consumption/hit kind explicitly instead of independently re-reading trigger edges in every panel.

**INFERRED — hover and focus:** intentional controller pointing acquires pointer ownership; laser hover then focuses/raises the hit window before moving to its matching point. This temporarily takes priority over eye dwell. When pointing yields, gaze resumes its existing dwell and cursor-memory behavior. Freeze gaze-selected focus while a button is held, while operating menus, and during placement; an explicit cross-window drag handoff may change the drop target. Repeated stationary controller aim must not overwrite physical trackpad motion or repeatedly reclaim focus. Gaze transitions restore remembered cursor position; pointer transitions place at the laser point without a restore-then-jump.

**INFERRED — mapping:** trigger down/up → `m` left edges, held trigger plus motion → `m` move (helper generates dragged events). Add a distinct secondary action, provisionally right B → right button; preserve grip for existing two-sided bends and switcher traversal. Add a `vector2` thumbstick action: dead zone, acceleration curve, fractional pixel accumulation and frame-time integration; send bounded pixel `wheel` deltas, +dy downward, and reset after capture loss/release. Exact physical B/stick paths and scroll sign must be checked against the installed Frame controller profile and worn behavior, not assumed from these bindings.

**INFERRED — compatibility:** keep legacy browser JSON. Negotiate native input support in helper `hello/info`, add a random connection input epoch and monotonic per-connection sequence `q`; reject native input before negotiation, stale epochs, nonfinite coordinates and unavailable sources. Reuse mouse/wheel/key/text field names. Add `intent` to focus: `gaze` restores memory, `pointer` raises and places at the supplied point, `drag` raises the destination and updates its fence without cursor-memory restoration or synthetic button edges. Add main-queue acknowledgements/barriers, for example:

```json
{"t":"focus","u":0.31,"v":0.12,"intent":"pointer","epoch":"opaque","q":20}
{"t":"m","e":"move","x":0.31,"y":0.12,"epoch":"opaque","q":21,"geometry":9}
{"t":"m","e":"down","b":0,"x":0.31,"y":0.12,"epoch":"opaque","q":22,"geometry":9,"i":7,"tv":123456}
{"t":"wheel","dx":0,"dy":16,"x":0.31,"y":0.12,"epoch":"opaque","q":23,"geometry":9}
{"t":"input-barrier","epoch":"opaque","q":24}
{"t":"input-ack","epoch":"opaque","q":24,"ok":true,"focusedSrc":"spatial:123"}
{"t":"release","epoch":"opaque","q":25}
```

**INFERRED — ordering/failure rules:** use a reliable bounded FIFO for focus, down/up, key, release and barriers; coalesce only consecutive unsent moves, never across an edge/barrier. On overflow, cancel ownership and release rather than silently drop an edge. At a target-stream transition, drain the old stream through a helper main-queue barrier, then focus/ack the new target before sending its movement/down; independent WebSockets have no shared arrival ordering. Keep transport source-bound—no unauthenticated arbitrary `src` field. On tracking loss, timeout, disconnect, Stop or mode change, release owned state; reconnect starts neutral and never replays held downs. Add a negotiated held-input heartbeat/expiry for a stalled connection. Release/up must remain usable when geometry becomes stale.

**INFERRED — negotiation/geometry format:** advertise `"nativeInput":1` and `"inputEpoch":"opaque"` in hello; each input-capable stream publishes `{"t":"input-geometry","v":1,"revision":9,"pictureSeq":44,"rect":[100,200,800,600],"contentUV":[0,0,1,1],"visible":true}`. Here `rect` is the global-point rectangle represented by `contentUV` within the displayed picture; capture padding is outside it. Associate updates with the picture they describe, and reject content clicks on padding or stale identity/crop. Mouse `geometry` echoes that revision; a geometry-independent up/release still clears ownership. Auxiliary identity/visibility changes invalidate the old revision even if a slot/window ID is reused. Use `{"t":"input-keepalive","epoch":"opaque","q":26}` while held; advertise the expiry interval in hello and process it independently of video delivery. These are proposed fields/messages, not existing protocol.

**INFERRED — helper focus confirmation:** change focus to return an observed result from frontmost app plus AX focused-window/modal-child state, rather than accepting an ignored AXRaise return. Serialize focus, fresh coordinate mapping, fence update and injection on main; map after focus readiness, not before. Return `input-ack` with failure/reason if readiness, permissions or geometry is invalid. Native should snap its confirmed focus state only on this acknowledgement. Preserve modal sheets rather than force the parent to become key.

**INFERRED — M1/I1:** route their picture UV to their own stream/crop; do not focus/raise the window behind an auxiliary hit. M1's current laser reveal can expand its four-millimetre lip (`native/main.cpp:1429–1434`, `spatial.hpp:288–315`); make that lip reveal-only and inject only over the visible picture. Freeze focused-window/menu anchoring while interacting with an open menu chain. I1 maps into the real global menu-bar status rect even though it is rendered on the shelf. Drop-downs use current slot rect and capture identity; reject hidden/retargeted slots and wait for matching fresh-picture geometry. Preserve native shelf/switcher trigger ownership, including dismissal clicks. The October 26 pinned-shelf/system-surface decisions remain the direction; input should follow actual shelf geometry and support subsequently admitted real Mac surfaces, without building a replacement launcher (`ISSUES.md:647–658`).

**INFERRED — cross-window drag:** retain the original injected button and disconnect owner across A → B. Barrier A, raise/expose B with `intent:"drag"`, switch the fence to the validated drop target plus permitted menus/children, then emit dragged motion at B's global point and eventually one up there. Do not emit up on leaving A, interpolate across unrelated overlapped windows, invoke cursor-memory restoration mid-drag, or allow gaze to change the target. A ray gap freezes the last valid drag point; release with no target ends there. Abort/release if either required stream/window disappears. Raising an overlapping destination during an AppKit drag is a critical runtime experiment: the old separate-display NSTextView probe does not establish this shared-display or cross-app behavior (`SPATIAL.md:162–170`).

**INFERRED — trackpad coexistence:** arbitrate in the helper, which can observe both sources. Tag every helper-generated CGEvent with `eventSourceUserData`; observe external move/drag/scroll/button activity without AX calls in the tap. External pointer activity immediately invalidates queued remote hover/focus and gives local input priority; native reacquisition requires neutral buttons plus deliberate new controller activity, not a stationary ray. Preserve physical keyboard use/modifiers. Track physical and injected button ownership separately so remote cleanup does not post an up for a button currently held physically. Fence corrections must also be identified to avoid treating the helper's own correction as takeover. Do not suppress physical input to conceal contention. Precise classification of other software's synthetic events remains a test requirement; treating unrecognized external pointer activity as local is conservative.

**VERIFIED — API support for that proposal:** Apple defines an event-source user-data field; posting at the HID tap passes through taps at that location. Local hardware input is not suppressed by default. These APIs support tagging/observation but do not themselves implement ownership. See [CGEventField](https://developer.apple.com/documentation/coregraphics/cgeventfield), and the inspected SDK `CoreGraphics.framework/Headers/CGEvent.h:347–354`, `CGEventSource.h:163–171,185–205`.

## 5. Geometry, latency and remaining risks

**VERIFIED — scaling facts:** capture uses `pointPixelScale`, then `fitSize()` long-edge/pixel caps and even rounding; output preserves aspect ratio. Production input assumes the whole picture corresponds to the parent window frame. Capture reads status/displayTime attachments but ignores contentRect/contentScale/scaleFactor/screenRect. Native menu point scale is `panelWidth * 2 / decodedWidth`, assuming uncapped 2× capture. See `Capture.swift:52–65,261–303,553–564`, `SpatialShared.swift:83`, `native/main.cpp:1423`.

**INFERRED — geometry requirement:** publish a geometry revision tied to the displayed frame, including global capture rectangle and its content/padding mapping; a revision changes on identity/frame/crop changes, not merely cursor-hot feedback. Derive menu metres-per-point from confirmed logical window width, not decoded width. For example, a 2400-point window capped from 4800 to 1920 pixels makes the existing scale estimate 2.5× too large. Normalized input remains independent of capture caps only when it addresses the true displayed content region. Saved 3D width/pose and curvature should change the ray intersection, not multiply Mac points or resize the Mac window.

**VERIFIED — Apple geometry distinction:** [SCContentFilter.contentRect](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/contentrect) is in screen points and `pointPixelScale` converts points to pixels. [SCStreamFrameInfo](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo) exposes per-frame content rectangle/scale and screen/bounding rectangles. Installed headers are from **MacOSX26.5.sdk**, newer than this Mac's 26.3.1 runtime; they establish declarations, not runtime layout. Relevant header: `ScreenCaptureKit.framework/Headers/SCStream.h:266–274,404–437` beneath the SDK returned by `xcrun --sdk macosx --show-sdk-path`.

**VERIFIED / INFERRED — children:** the helper sets `includeChildWindows=true`, and the repository records a popover captured beyond its parent frame (`SpatialShared.swift:90–94`; `SPATIAL.md:515–519`; [Apple property](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/includechildwindows)). That does not establish its clickable global mapping. The current fence contains only parent window, menu-bar rect and discovered menu-bar/status surfaces; it omits arbitrary outlying child bounds (`SpatialShared.swift:58–64,246–267`). **INFERRED:** measure production frame content/padding and child hit bounds; extend mapping/fence or admit a separate child surface. Capture visibility alone does not prove input reaches it.

**VERIFIED — edge/retarget risks:** `panelToGlobal()` maps exact 1.0 to maxX/maxY, whereas the separate `NormalizedPoint.point()` helper keeps the edge half a point inside. Fence filtering covers move/drag only, not button-down/up or wheel. Menu discovery recognizes top-touching layer-101 menus and Control Center layer 22, with only four slots; a side submenu or other system panel is not guaranteed admission. See `SpatialSharedPolicy.swift:35–39,56–58`, `SpatialStreams.swift:15–20`, `SpatialCursorFence.swift:21–38`, `SpatialShared.swift:255–267`.

**INFERRED — latency path:** sampled controller → native arbiter/queue → existing WebSocket through the SSH reverse tunnel → Swift parser/main queue → focus/CGEvent → app/WindowServer → SCK → VideoToolbox → tunnel → native decode/upload → SteamVR compositor. Source support: `session.hpp:200–231`, `video.hpp:442–513`, `ui/frame_macview.py:899–904`, `Sources/main.swift:844–880`. Enable prompt outbound servicing for ordinary input streams and measure queue/backpressure as well as focus readiness. Target handoffs add acknowledgement round trips. Still-window promotion also matters: pointer hover must wake the chosen window directly or ensure companion live-set selection follows it promptly.

**VERIFIED / INFERRED — latency evidence limit:** input IDs and synchronized timestamps already correlate injection to a subsequent captured frame (`Sources/main.swift:252–287,745–751`; `Stats.swift:23–60`); native reports upload timing with `vsync=0` (`native/video.hpp:414–423`). **INFERRED:** retain those stages, add acknowledged focus/injection timing and actual compositor/display evidence. A subsequent frame need not contain the event's visual effect, and upload time is not photon time; no latency number is established by this inspection.

**INFERRED — headset acceptance still required:** confirm installed controller profile/button labels, laser alignment and UV at edges/seams for every bend, hover ownership with a real trackpad, gaze dwell/ack behavior, menu/status selection and submenu reachability, long drag/drop across overlapping apps, physical typing/shortcuts/IME into the confirmed window, capture-cap/resizing behavior, source/target disconnect cleanup, and real input-to-visible-response timing. Protected prompts, password fields and the October 26 real-system-surface/Laptop Screen route remain separate capture/admission unknowns; missing native input cannot establish their support.
