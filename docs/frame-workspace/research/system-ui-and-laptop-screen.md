# FW-15 R1 — real system UI, Laptop Screen, and Dock

**VERIFIED — research scope:** checkout `2f8065534f5a20b2f20cacf122af5bc4e116ab12`, detached; macOS **26.3.1 (25D2128)**, Apple M4; Xcode 26.6 with macOS 26.5 SDK. No tracked edits, app/helper/virtual-display launches, headset access, input injection, or window manipulation occurred. Evidence is source inspection, Apple documentation, and passive CG/AX metadata. No pixels were captured.

**INFERRED — recommendation:** implement S1 as independently discovered, **unmoved** surfaces on whichever Mac display actually hosts them; implement S2 as a built-in-display stream excluding the cover, with an explicit input mode. ## Passwords: three different gates

1. **VERIFIED — pixels:** current Apple documentation calls [`NSWindow.SharingType.none`](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none) legacy and advises against using it to hide capture. The local SDK’s older prose still describes it as preventing capture (`SDK/AppKit.framework/Headers/NSWindow.h:83–89,520–522`). **INFERRED:** neither that property nor CG sharing 0 is a reliable macOS-26 SCK exclusion test. Actual SecurityAgent/Touch ID image behavior is still unverified; system-specific protection may exist independently.
2. **VERIFIED — keyboard observation:** secure event input limits keyboard delivery/monitoring to the focused app (`SDK/Carbon.framework/Frameworks/HIToolbox.framework/Headers/CarbonEventsCore.h:2971–2984`). It does not document a screen-pixel rule. **INFERRED:** do not diagnose a blank capture from secure-input state, or use that state to identify which window is a password prompt.
3. **VERIFIED — injection:** helper events go to `.cghidEventTap` (`Input.swift:115–129,179–209`), requiring its existing permissions. **INFERRED:** neither successful AX access nor readable pixels proves a secure prompt accepts synthetic clicks/keys. Conversely, no blanket Apple technical prohibition was established here. Touch ID itself needs physical authentication. Fail to local Mac interaction instead of trying privileged injection or alternate capture APIs.

## Discovery: concrete changes

**VERIFIED — present gaps:** normal discovery watches only regular apps, one AX window-created notification, plus a one-second CG refresh (`Spatial.swift:60–139`). Admission requires layer 0, size ≥120×80, regular app, standard AX window and excludes Spotlight/Dock/Notification Center/etc. (`SpatialPolicy.swift:74–86`; `Spatial.swift:831–843`). All observed system hosts use accessory activation policy 1. The separate menu watcher polls CG every 0.1 s but recognizes only its narrow menu rules (`SpatialShared.swift:174–179,229–269`).

**INFERRED — extension rules:**

- Keep `SpatialWindowPolicy` as the **movable app-window** policy. Do not just remove excluded names: `Spatial.swift:246–254,289–297` would otherwise try to move admitted system windows. Add a distinct nonmoving surface classifier/registry in `SpatialSharedPolicy.swift` / `SpatialShared.swift` (or a dedicated `SpatialSystemSurfaces.swift`).
- Identify owner by **bundle ID + PID**, not localized process name. Allow Spotlight, measured Control Center/menu cases, Notification Center non-desktop surfaces, SecurityAgent/helpers, LocalAuthentication UIAgent, open/save XPC service, loginwindow dialogs, and measured warning hosts. Combine known owner with positive bounds, current ordered visibility, AX role/subrole/modal/parent evidence where available; never admit all Dock/Notification Center canvases or every layer-0 helper window. Unknown candidates remain visible via fallback/diagnostics until classified.
- Observe accessory/XPC hosts too. Add supported AX created/sheet-created/focused-window/main-window/menu-open/menu-close events; attach destroyed/move/resize notifications to discovered elements. Keep registrations that succeed when another notification is unsupported. Use bounded AX timeouts off the cursor-tap thread. AX constants exist in `SDK/ApplicationServices.framework/Frameworks/HIServices.framework/Headers/AXNotificationConstants.h:108–123,162–220,283–287`; availability does not mean every host emits them.
- Use NSWorkspace launch/terminate/activate/hide/unhide and active-Space/screen-change notifications to invalidate state; they are hints, not complete transient-window events. Retain fast **CG metadata** polling for system/menu candidates and slower baseline discovery. Refresh SCK availability on candidate changes with one outstanding enumeration, debounce and backoff; do not poll SCK at every cursor event.
- Store `(windowID, PID, generation)`, kind, rect, owning display intersections, parent evidence, capture route and visibility revision. Diff visibility/geometry, not merely new IDs. Reused/off-screen Spotlight windows and the prior menu-ID reuse show why. Add CG `sharingState` to diagnostics in `Capture.swift:70–101`; never use it as a hard capture-deny rule.
- Prefer an independent window stream when available, then current-display crop excluding the cover. Preserve the existing generation/sequence and first-fresh-picture gates (`SpatialShared.swift:342–443`; `native/host.hpp:85–90`). A timeout or a complete but blank picture needs an explicit unavailable state; “stream started” is not readable content. Generic black-pixel tests alone cannot distinguish valid dark UI from protection.
- For **Dock enumeration**, use `excludingDesktopWindows(false, ...)`: Apple explicitly includes Dock among [desktop windows excluded by true](https://developer.apple.com/documentation/screencapturekit/scshareablecontent/getexcludingdesktopwindows(_:onscreenwindowsonly:completionhandler:)). Current `Capture.swift:244` uses true. A display crop can avoid depending on Dock enumeration altogether.

## Input, cover, and levels

**VERIFIED — runtime level values:** `CGWindowLevelForKey` returned normal **0**, floating/torn-off menu **3**, modal panel **8**, utility **19**, Dock **20**, main menu **24**, status **25**, popup menu **101**, overlay **102**, help **200**, screen saver **1000**, assistive-high **1500**. Actual observed Spotlight is **23**, Control Center prior popover **22**, current Notification Center container **21**; these are observed values, not public semantic constants for all future windows.

**VERIFIED — cover:** `Spatial.swift:547–555` creates a borderless black window at `.floating` (3), joins Spaces, and orders it front. It does not set `ignoresMouseEvents`. Captures explicitly exclude its window ID only for existing display-based auxiliary sources (`SpatialShared.swift:379–385`). The comment that system dialogs remain usable is broader than the layer-0 warning evidence supports.

**INFERRED — answer:** a surface **does not have to move to the shared display**. The same global event route can address built-in coordinates, provided the fence permits them and the cover/other windows do not intercept the point. Excluding the cover from capture changes output pixels; **it does not change hit testing**. Surfaces above level 3 can be above the cover; level-0 dialogs remain behind it. Set the cover mouse-transparent using documented [`ignoresMouseEvents`](https://developer.apple.com/documentation/appkit/nswindow/ignoresmouseevents), keep it non-key/nonactivating, and validate real clicks into normal windows beneath it. Do not raise its level and assume capture exclusion also routes input.

**VERIFIED — current routing:** `SpatialFocus` allows focused app rect + menu bar + menu surfaces (`SpatialShared.swift:23–64`). The fence constrains **moves and drags**, not mouse-down or keyboard events (`SpatialCursorFence.swift:37–71`). Session maps normalized picture coordinates to `capture.frameRect`, raises spatial parent on key/mouse-down, and posts input (`main.swift:738–742,844–887`). Native currently handles shelf/switcher actions and focus, while auxiliary hits block underlying interactions (`native/main.cpp:1463–1545`; `native/video.hpp:425–432`); content input is still missing as recorded in `SPATIAL-AUDIT.md`.

**INFERRED — required input contract:** add a target lease for app window, system surface, Laptop Screen or Dock. Before a move, atomically install its allowed rect(s), then send real move/down/up/wheel events with global coordinates. Laptop mode permits the full built-in; system mode permits its actual rect plus related submenu/child rects. Restore the previous app fence on exit. Preserve drag ownership until release; release held buttons/keys on hide, disconnect, Stop and generation change. A modal system surface should suspend gaze-driven activation of app panels behind it. Do not call the normal app-activation routine for every menu/Dock/notification hover: it can dismiss the UI or steal its keyboard focus. Typing goes to the **actual key window**, not to the panel merely being rendered.

**INFERRED — geometry risk:** children outside a parent’s bounds need capture-to-global mapping and fence coverage too. Existing `SCKSource` uses the parent/crop rect and reads only status/displayTime attachments (`Capture.swift:453–464,553–564`). Compare actual SCK [`screenRect`](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo/screenrect), content/bounding rect and scale against clicks before claiming child capture also makes protruding children interactive.

## S2 Laptop Screen

**VERIFIED — existing building blocks:** `SCKSource(.display(id))` already creates `SCContentFilter(display:excludingWindows:)`, maps display points, downsizes and captures NV12 without audio (`Capture.swift:232–304`). The auxiliary source already supplies the cover ID for exclusion. Apple [documents the exclusion filter](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init(display:excludingwindows:)); SDK `SCStream.h:149–154` explicitly includes desktop and Dock.

**INFERRED — implementation:** add a `laptop` source resolved by built-in display identity, available only during Spatial Mode. Explicitly exclude the current cover SCWindow, include menu bar, rebind on display/filter changes, and reject stale input generations. Keep the cover locally black but mouse-transparent. Selecting Laptop Screen grants its whole-display fence and global pointer mapping; clicking selects the underlying Mac target naturally. Do not raise a previously focused shared app on Laptop typing. If the cover cannot be resolved/excluded, report unavailable rather than silently streaming a black cover.

**INFERRED — cost (arithmetic, not benchmark):** this mode’s full backing size is **8.42 MP**; with an example `maxLong=1920` cap, `fitSize` gives approximately **1920×1246 = 2.39 MP** (`Capture.swift:54–65`). One NV12 image is approximately 12.6 MB / 3.59 MB respectively before additional buffering. A live S2 stream adds capture/composition, encoder, network, decoder and texture work even when it duplicates other panels; downscaling reduces codec work but does not establish an equivalent reduction in WindowServer work. Include its actual coded dimensions in the existing **18 MP** default budget (`ui/frame_macview.py:153–162`). Use low-rate/still standby and promote on selection, reserving room for a critical system prompt. No new throughput/latency measurement was made.

**INFERRED — limits:** S2 cannot reveal protected pixels, accept blocked secure input, or show a missed surface that is **only on the hidden shared display**. For a known missed shared-display surface, use S1’s crop of that display. A truly universal fallback would need an additional shared-display view/selector, which exceeds the currently approved Laptop Screen behavior and needs a separate design decision. If capture or secure input fails, a user-invoked uncover/Stop path must restore direct Mac access and release the fence; do not leave the user trapped behind the cover.

## Recommended implementation sequence and Dock verdict

**INFERRED — staged scope, no duration estimate:**

1. **Reliable foundation and input:** resolve the installed-pair/idle-auxiliary blockers recorded in `SPATIAL-AUDIT.md`; add native content move/down/up/scroll/key/release transport (`native/main.cpp`, `overlay.hpp`, `video.hpp`) and target leases in helper `main.swift`, `Input.swift`, `SpatialShared.swift`, `SpatialCursorFence.swift`. Acceptance: real app, menu, drag, disconnect cleanup; no stale input after a surface changes.
2. **S2 first:** built-in `laptop` source/filter and mouse-transparent cover (`Capture.swift`, `Spatial.swift`, `main.swift`), companion lifecycle/budget (`ui/frame_macview.py`), native laptop panel role/focus behavior (`host.hpp`, `main.cpp`). Acceptance: readable content beneath cover and correct whole-display input; recover locally on failure.
3. **S1 registry and presentation:** independent nonmoving system-surface discovery/classification and capture fallback (`SpatialSharedPolicy.swift`, `SpatialShared.swift` or new `SpatialSystemSurfaces.swift`, `Capture.swift`, `main.swift`), companion surface reconciliation, native `system` role placed in front without stealing menu/modal focus. Keep app-moving exclusions. Carry kind, owner, rect/display, generation and capture/input availability. Prioritize modal auth/file panels over notifications; avoid duplicate parents/children only when attachment/capture inclusion is established. Acceptance includes Spotlight Apps, XPC panel, status menus and a real auth prompt, with honest unavailable fallback.
4. **Dock experiment after input works:** use a crop of the actual Dock-hosting display; AX item bounds provide an initial crop, but allow animation/magnification and separate menus/stacks beyond it. Update crop and input rect together. Apple’s [Dock settings](https://support.apple.com/guide/mac-help/change-desktop-dock-settings-mchlp1119/26/mac/26) tie magnification to pointer hover and auto-hide reveal to the screen edge. Native gaze/laser must drive the **real Mac cursor** to get real Dock hover/magnification when enabled; merely highlighting its headset texture will not animate macOS.
